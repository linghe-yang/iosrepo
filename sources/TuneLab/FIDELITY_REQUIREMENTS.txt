移植范围与完成标准（按用户最新要求修正）

这项工作的目标是用户提供 AndroidTuneLab-3.2.apk 的精准移植。
原项目的 UI、名称、图标、功能和算法是目标，不另外设计一个钢琴调律应用。

产品身份

桌面显示 Piano Tuner；内部 TuneLab 名称、原图标、原按钮图、关于信息和帮助内容均以 APK 为依据。
版本资源保持原 3.2 身份；iOS 构建号和移植状态在发行说明中明确记录。
不能继续以 PianoLab 的名字、生成的键盘图标或另一套界面作为交付结果。

UI

所有 42 个原 Activity、相关对话框/菜单/列表、横竖屏与大小屏布局、亮暗主题都要逐项覆盖。
文字以原 APK 的语言资源及代码中的动态字符串为准；不能擅自全部翻译成中文或重写提示。
图标、按下态和原资源直接复用；不能用看起来接近的系统符号代替。
字体、尺寸、颜色、间距、透明度、可见状态、层级和布局要在固定条件下用截图核对。
点击、长按、拖动、滑动、手势、返回/退出、保存提示、键盘和动态选项必须依照原代码。
读到 XML 和画出相似页面不能当作全部 UI 完成。
Android/iOS 系统状态栏、系统权限和输入法按平台适配，单独列差异，不混入应用界面验收。

功能与数据

原设置列表、调律曲线编辑、非谐性与测量序列、泛音表、自动选音/选泛音、多泛音、相位和锁定全部保留。
过拉状态、校准、非平均律、文件及文件夹操作、备注、传输、考试等逐条建立原行为用例。
授权相关限制按用户此前的明确要求不作为使用门槛；不能借此删掉无关的原功能或算法。
调律文件字段、逐音泛音、自定义偏移、测量次数、原保存音分、考试基准和未知字段要明确处理。
“支持 .tun”不等于只读若干参数并重新计算其他全部内容；普通/考试导入语义不能合并。

算法

37 个原 JNI 接口及其内部声音处理链都要核对，而非只迁移几个公式。
不以独立 FFT 测音器、频差动画、泛音中位值或另外的自动选音规则替换原状态机，并声称完全等价。
原音频触发、解调/滤波、相位速度和质量、自动切换、频谱处理、锁定、校准、无效值都属于算法范围。
已通过的 11 个声音、190 组曲线、1,056 音过拉、32 组旧版拟合只是相应测试集的证据。
新增状态与边界要继续与原 APK/原指令对照；不静默改原程序的奇怪行为。
反编译 Java 的类型/算术歧义必须用 Smali 或真实运行核对。

发布

完成状态至少分别记录：原资源一致、页面布局/状态验证、交互验证、算法验证、目标 iOS 设备验证。
在全部要求完成之前，不使用“精准移植完成”“全功能一致”或“保证直接使用”作为发布结论。
PianoLab 只保留为前期原型和数学参考，不能通过改名/换图标升级成所谓精准移植版。
